# Contributing

Thanks for helping keep this list useful.

## What belongs here

Something that helps a person build, verify, regulate or understand a European Digital Identity Wallet implementation. Concretely:

- Specifications and regulation that the ARF actually depends on.
- Implementations someone can run: wallets, issuers, verifiers, libraries.
- Test and conformance tooling.
- National and consortium work, including specifications published by member states.

## What does not

- Marketing pages with no technical substance.
- Products with no public documentation, no source and no way to evaluate them.
- Abandoned repositories. A library with no commits in two years is not a resource, it is a trap. If something here has gone stale, open an issue and it will be moved or removed.
- Blog posts, unless they are the clearest available explanation of something otherwise undocumented. This is a list of resources, not a reading list.

## How to add an entry

1. Fork the repository and add your entry to the relevant section.
2. Keep the format: `- [Name](link) - Description ending with a period.`
3. Keep the description to one line. Say what it *is* and, where it helps, what it is *for*. Assume the reader knows what a wallet is and does not know why they should click.
4. Keep sections alphabetical only where they already are. Most sections are ordered by usefulness, not alphabet, which is a deliberate choice.
5. One entry per pull request where possible, so a disagreement about one link does not block five good ones.

## Standards for descriptions

Write the sentence you would want if you had never seen the project. "Kotlin library" is not a description. "OpenID4VCI in Kotlin, wallet role" is.

No superlatives, no "powerful", no "easy to use". If a project is the only implementation of something, say that, because it is a fact and it is useful.

## Removing entries

Open an issue with the reason. Staleness, a dead link, or a project that has been superseded are all good reasons. Disliking a vendor is not.
